# Meally — документация

Живёт в репозитории рядом с кодом. Правится в тех же PR, что и код.

## Структура

```
docs/
├── README.md              ← ты здесь
├── 01-product.md          Позиционирование, ЦА, границы продукта
├── 02-decisions.md        Журнал решений (ADR). Только дописывается
├── 03-domain.md           Модель данных, инварианты
├── 04-content.md          Правила рецептов и ротаций, скрытый глютен
├── 05-formulas.md         TDEE, дефицит, прогноз, плато
├── 06-ux.md               Спека четырёх вкладок
└── 07-stack.md            Стек, окружение, деплой

backlog/
├── README.md              Как устроена тикетница
└── epics/
    ├── E0-foundation.md
    ├── E1-profile.md
    ├── E2-goal.md
    ├── E3-content.md
    ├── E4-progress.md
    ├── E5-grocery.md
    ├── E6-cooking.md
    └── E7-account.md
```

## Как этим пользоваться

| Хочу... | Иду в |
|---|---|
| Понять, зачем это всё | `01-product.md` |
| Узнать, почему сделано так, а не иначе | `02-decisions.md` |
| Написать миграцию | `03-domain.md` |
| Добавить рецепт | `04-content.md` |
| Тронуть расчёты | `05-formulas.md` |
| Верстать экран | `06-ux.md` |
| Взять задачу в работу | `backlog/epics/*` |

## Правила

1. **Решения — только в `02-decisions.md`.** Не дублировать в других документах: там ссылка вида `см. ADR-004`.
2. **Один документ — одна тема.** Если тянет дописать раздел не по теме, это сигнал завести новый документ.
3. **Бэклог — не место для обоснований.** В тикете «что» и «как проверить». «Почему» — в ADR.
4. **Документ устарел = баг.** Правится в том же PR, что и код.
