# 05 — Формулы и расчёты

Всё, что здесь описано, должно быть покрыто юнит-тестами. Ошибка в этих формулах не видна глазом, но ломает продукт целиком.

## 1. BMR — Mifflin-St Jeor

```
мужчины:  BMR = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст + 5
женщины:  BMR = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст − 161
```

Вес берётся как **скользящее среднее за 7 дней**, не последний замер.

## 2. TDEE

```
TDEE = BMR × activity_factor
```

| Фактор | Кому |
|---|---|
| 1.2 | сидячая работа, нет тренировок |
| 1.375 | 1–3 тренировки в неделю |
| 1.55 | 3–5 тренировок |
| 1.725 | 6–7 тренировок или физический труд |

Офисная работа + зал 3–4 раза в неделю → **1.55**.

## 3. Дефицит

```
дефицит_ккал_в_день = weekly_rate_kg × 7700 / 7
target_kcal = TDEE − дефицит
```

7700 ккал ≈ 1 кг жировой ткани.

**Ограничитель:** дефицит не превышает 20 % от TDEE. Если превышает — понизить `weekly_rate_kg` и предупредить пользователя.

Пример: 80 кг, TDEE 2700, темп 0.35 кг/нед → дефицит 385 ккал → target 2315 ккал.

## 4. Макросы

Порядок расчёта важен: белок и жир фиксируются, углеводы — остаток.

```
protein_g = вес × 1.8..2.2        # при дефиците брать верхнюю границу
fat_g     = вес × 0.8..1.0        # ниже 0.8 не опускать
carbs_g   = (target_kcal − protein_g×4 − fat_g×9) / 4
```

Если `carbs_g` выходит отрицательным или меньше 80 г — дефицит слишком агрессивный, понизить темп.

Пример: 80 кг, 2315 ккал → белок 176 г (704 ккал), жир 68 г (612 ккал), углеводы 250 г.

## 5. Скользящее среднее веса

```
avg(d) = среднее всех замеров веса за [d−6, d]
```

Если в окне меньше 3 замеров — среднее не показывается, вместо него «нужно больше замеров».

Это единственное число, которое показывается пользователю как «твой вес». Сырые замеры видны только на графике точками.

## 6. Плановая траектория

```
план_вес(d) = start_weight − weekly_rate_kg × (d − started_on) / 7
```

Для талии линейная траектория **не строится** — она движется рывками. Показывается только факт и остаток до цели.

## 7. Прогноз даты достижения

Считается по фактической скорости, а не по плановой.

```
фактическая_скорость = (avg(сегодня) − avg(14 дней назад)) / 2   # кг/нед
остаток = avg(сегодня) − target_weight
прогноз_дней = остаток / фактическая_скорость × 7
```

Правила:

- До накопления 14 дней данных — показывается плановая дата с пометкой «предварительно»
- Если фактическая скорость ≤ 0 при активной цели на снижение — прогноз не показывается, показывается «плато»
- Прогноз округляется до недели: «примерно к 14 марта», не «через 37 дней»

## 8. Статус относительно плана

```
отклонение = avg(сегодня) − план_вес(сегодня)
```

| Отклонение | Статус |
|---|---|
| < −0.7 кг | опережаешь |
| −0.7 .. +0.7 кг | идёшь по плану |
| > +0.7 кг | отстаёшь |

Порог 0.7 кг — это шум воды. Более узкий порог будет дёргать статус каждый день.

## 9. Правило плато

```
если фактическая_скорость < 0.1 кг/нед на протяжении 14 дней:
    предложить снизить target_kcal на 150
```

**Предложить, не сделать автоматически.** Автоматическое урезание калорий без ведома пользователя — плохая идея.

Ограничитель: `target_kcal` не опускается ниже `BMR × 1.1`. При достижении этой границы вместо снижения калорий предлагается диет-брейк — 1–2 недели на поддержании.

## 10. Достижение цели

Цель считается достигнутой при достижении **primary-метрики** (ADR-002).

```
waist_primary:  avg_waist <= target_waist_cm
weight_primary: avg(сегодня) <= target_weight_kg
```

При достижении — `Goal.status = :achieved`, предложение перейти в режим поддержания с `target_kcal = TDEE`, пересчитанным на новый вес.

## 11. Масштабирование ротации

```
scale = target_kcal / rotation.base_kcal
```

Применяется ко всем количествам ингредиентов. Валидация: `0.7 <= scale <= 1.4`. Вне диапазона — ротация не подходит, нужна другая с другим `base_kcal`.

Специи и соль **не масштабируются** — помечаются в справочнике флагом фиксированного количества.
